## The task

Give `nera validate`, `nera check` and `nera build --check` a `--json` flag, so an
AI agent (and later the MCP server) gets the findings as one machine-readable
object instead of parsing the human report. With `--json`, stdout holds exactly
one JSON object and nothing else; every log line (the engine's build log, plugin
output) goes to stderr; the exit code is the same as without the flag. This is
layer L3 of `ROADMAP-ai.md`, the first part of slice 3.

### Decisions already taken for you

- **Shape on success:** `{ "ok": <bool>, "results": [ … ] }`. `results` is the
  validator's array **unchanged** (same objects, same order). `ok` is `true` exactly
  when the exit code is 0, i.e. `!hasErrors(results)` — warnings alone keep
  `ok: true`.
- **Shape on failure** (the command throws: no `public/` for `nera check`, the
  build fails, a config the validator cannot read): stdout
  `{ "ok": false, "error": "<the error message>", "results": [] }`, exit code 1 —
  the same code text mode ends with. The `run*` function catches in JSON mode and
  returns 1; it does not rethrow (so the bin's `❌` line does not appear). Text
  mode keeps throwing as today.
- **`nera build --json` without `--check`:** allowed; prints
  `{ "ok": true, "results": [] }` with the build log on stderr, exit 0. A failed
  build prints the failure shape.
- **`nera build --check --json`:** one object only — the check's `{ ok, results }`
  (no separate build section). The build log goes to stderr.
- **Output:** `JSON.stringify(value, null, 2)` plus one trailing newline, written
  to stdout. No colours, no human note ("not proof of compliance") in the JSON.
- **Logs to stderr:** for the duration of the command in JSON mode, route
  `console.log` / `console.info` / `console.debug` to stderr and restore them in a
  `finally`. Write the JSON object itself through the real stdout. Whether you
  also guard raw `process.stdout.write` is your call — record it under Decisions.
- **One code path:** put the JSON-mode handling in one small shared module (e.g.
  `src/json-output.js`), used by all three commands, not copied into each. Keep
  the existing call signatures working (`runValidate({ cwd })`,
  `runCheck({ cwd })`, `runBuild(args)` — the existing tests call them that way);
  add the option in a backward-compatible way. `bin/nera.js` passes `--json`
  through from `rest`.
- Unknown flags stay ignored, as today.
