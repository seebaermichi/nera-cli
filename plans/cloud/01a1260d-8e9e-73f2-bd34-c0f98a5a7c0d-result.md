# Result — --json for validate, check and build --check (01a1260d-8e9e-73f2-bd34-c0f98a5a7c0d)

## Plan

1. `src/json-output.js` — one helper, `runJson(body)`: while `body` runs,
   `console.log`/`info`/`debug` and raw `process.stdout.write` go to stderr;
   afterwards (in a `finally`) both are restored. The body returns the
   validator's results (sync or as a promise); the helper writes
   `{ ok, results }` (`ok` = `!hasErrors(results)`) or, when the body throws,
   `{ ok: false, error, results: [] }` through the real stdout as
   `JSON.stringify(value, null, 2) + '\n'`, and returns the exit code
   (0/1). Sync bodies stay sync, so `runValidate`/`runCheck` keep returning a
   number.
2. `runValidate({ cwd, json })`, `runCheck({ cwd, json })`: with `json`, call
   `runJson(() => validateSite/validateOutput({ cwd }))`; text path untouched.
3. `runBuild(args)`: `--json` in `args` → `runJson(async () => { await run();
   return check ? validateOutput({ cwd }) : [] })`; text path untouched.
4. `bin/nera.js`: pass `{ json: rest.includes('--json') }` to validate/check;
   add `--json` to the usage lines of build, validate, check.
5. `template/AGENTS.md` (Commands section, Nera-owned part) and `README.md`
   (commands table + a "Machine-readable output" section).
6. Tests: `test/json-output.test.js` — in-process per command (clean,
   warnings-only, error; exit code equals text mode; stdout parses; results
   deep-equal the validator's), `check --json` without `public/`, and
   child-process runs of `bin/nera.js` proving the whole stdout is JSON and
   the build log is on stderr.
7. `npm run lint && npx vitest run`, then fill in this file and push.
