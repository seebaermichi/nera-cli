## Summary

`nera validate`, `nera check` and `nera build` take `--json`. One shared helper,
`src/json-output.js` (`runJson`), routes console.log/info/debug and raw
`process.stdout.write` to stderr while the command runs, then writes exactly one
object to stdout (`{ ok, results }` or `{ ok: false, error, results: [] }`) and
returns the exit code text mode would end with. The three `run*` functions take
the option backward-compatibly; `bin/nera.js` passes `--json` through and lists
it on the usage lines. `template/AGENTS.md` and `README.md` document it; a new
`test/json-output.test.js` covers it in-process and with child processes.

## Decisions

- JSON mode also re-routes raw `process.stdout.write` to stderr (not only
  `console.log`/`info`/`debug`), so plugin output that bypasses `console` cannot
  break the object; the object itself is written through the restored stdout
  after the command finished. `console.warn`/`console.error` already go to
  stderr and are left alone.
- `runJson(body)` stays synchronous for a synchronous body, so `runValidate` and
  `runCheck` keep returning a number in both modes; `runBuild` returns a promise
  as before.
- `ok` and the exit code come from one place: `ok = !hasErrors(results)`, exit
  code `ok ? 0 : 1`; a thrown error gives `ok: false`, exit 1, and is not
  rethrown, so the bin prints no `❌` line in JSON mode.
- `nera build --check --json` calls `validateOutput({ cwd: process.cwd() })`
  directly inside the JSON body instead of going through `runCheck`, which
  would print a second object; the check is still the one shared validator
  function.
- `results` is passed through unchanged, so it carries whatever the installed
  `@nera-static/validate` adds: with 1.2.0, `nera check` findings also have a
  `source` field (the page the HTML came from). The documented shape names the
  five guaranteed fields.
- The bin sets `process.exitCode` for `validate` and `check` instead of calling
  `process.exit()`, so a large JSON object written to a pipe is never cut off
  by an early exit (stdout writes to pipes are asynchronous on macOS). Both
  commands are synchronous and leave nothing on the event loop, so the exit
  code and timing are unchanged; `build` already used `process.exitCode`.
- `--json` is written on the command's own usage line (not a continuation line),
  because `test/agents-commands.test.js` only matches flags on a
  `  nera <command>` line.

  process's stdout — that server will probably want the `{ ok, results }`

  case today (core's `run()` awaits all its work).

  child-process tests are the real proof of a pure stdout.
- The `source` field in check results comes from validate 1.2.0 (lockfile);
  I did not run against validate 1.4.1.
- The bin change from `process.exit()` to `process.exitCode` for
  validate/check is the one behavioural change outside JSON mode (see
  Decisions); output and exit codes are identical (verified against `main`).
