## The task

Give `nera new` starter kits: `nera new my-site --starter <spec>` scaffolds the
base template, then lays a **starter kit** (a whole ready-to-edit site: pages,
config, optional theme overrides, assets, dependencies) over it, merges the
starter's dependencies into the site's `package.json`, and applies `--name` /
`--lang` to `config/app.yaml`. Without `--starter`, on a TTY only, `nera new`
asks "What are you building?" from a list fetched from the npm registry (keyword
`nera-starter`, official `@nera-static/` ones first), falling back to a list
bundled with the CLI when offline, then asks the site name and language. Without
a TTY, or with `--yes`, it never asks anything and behaves exactly as today. No
starter package is published yet (that is a separate issue); you prove the
mechanism with a minimal starter **fixture inside this repo's tests**.

### Decisions already taken for you (by the maintainer's session)

1. **Starter package shape.** A starter is a directory with a `package.json`
   whose `nera.starter` is `{ "label": "…", "description": "…" }`. Anything
   without that field is refused: "`<spec>` is not a Nera starter: its
   package.json has no `nera.starter` field." Copied from the starter, over the
   base template, file by file (starter wins): **only** `pages/`, `config/`,
   `theme/`, `assets/`, `plugins/` and `.neraignore`. Never its `package.json`,
   `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/`, `node_modules/` or anything
   else. Its `README.md`, if present, is printed after "Done" (not copied).
2. **Dependency merge.** The starter's `dependencies` are merged into the site's
   `package.json` `dependencies`; the site's own `@nera-static/nera` entry is
   never overwritten. `devDependencies`, `scripts` and everything else in the
   starter's manifest are ignored.
3. **Theme.** If the starter's `config/app.yaml` sets `theme:`, the base
   template's starter views (first line carries `nera:scaffold-default`) are
   left out, exactly as `--theme` does today. `--starter` together with
   `--theme` is an error ("A starter brings its own theme; use --starter or
   --theme, not both.").
4. **Spec forms**, validated before anything is written, the same style as
   `validateThemeSpec`: bare name (`blank` → `@nera-static/starter-blank`),
   package name (`@acme/starter-x`, unscoped `nera-starter-x`), GitHub URL
   (`https://github.com/<owner>/<repo>` with optional `.git` and `#<ref>`, and
   `github:<owner>/<repo>[#<ref>]`), local path (`./x`, `../x`, as
   `LOCAL_THEME`). Anything else: an error naming the four forms.
5. **Fetching.** A local path is read in place. Package and GitHub forms go
   through `npm pack <spec> --ignore-scripts --pack-destination <tmp>` (GitHub
   forms as `github:<owner>/<repo>[#ref]`), then `tar -xzf` into a temp dir
   (npm tarballs unpack to `package/`). `--ignore-scripts` is mandatory: a git
   dependency's `prepare` script must never run. Temp dirs are removed in a
   `finally`. Make the pack/extract step injectable (an option on the exported
   function) so tests never touch the network.
6. **`--name` / `--lang`.** `--name "Brot & Zeit"` sets the top-level `name:`
   in `config/app.yaml`, `--lang de` sets `lang:`, each replacing the existing
   top-level line or appending one if absent, applied **after** the starter's
   config is copied, with or without a starter. Write the name as a JSON
   string (`name: "Brot & Zeit"` — valid YAML, safe for `:`/`#`/quotes);
   validate `--lang` as `/^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$/`. Line-based edit,
   no YAML library: keep every other line and comment as is. Do not touch the
   `translations:` block. The npm package/folder name stays the positional
   project name.
7. **Picker.** Runs only when `process.stdin.isTTY && process.stdout.isTTY`, no
   `--yes`, and no `--starter`. Questions, each skipped when its flag is given:
   "What are you building?" (numbered list; first entry "Empty — the base
   template, no starter", which is the default), "Site name" (default: the
   template's `My Nera Site` or the starter's own `name:`), "Language"
   (default `en`). Enter accepts the default. Without a TTY or with `--yes`:
   no starter, no prompt, today's output and files byte-for-byte (keep an
   existing test or add one that proves this).
8. **Starter catalog.** Search
   `https://registry.npmjs.org/-/v1/search?text=keywords:nera-starter&size=50`
   with a timeout of about 3 s (`AbortSignal.timeout`). Sort `@nera-static/`
   packages first, then alphabetically. Label/description: from the search
   result's `description`; do **not** fetch each manifest. Display name: the
   bare name for official ones (`blank`), the full package name otherwise. On
   any failure (offline, timeout, non-200, bad JSON) use the bundled list,
   `src/starters.json` (or `.js`), which holds the official starters to offer
   offline — today only `{ "name": "blank", "package":
   "@nera-static/starter-blank", "label": "Blank", "description": "The smallest
   Nera starter: one page, one layout." }`. Comment that the list is
   hand-kept and grows with each published official starter. The fetch is
   injectable for tests.
9. **Errors** say what is wrong, where, and what to do (conventions). A failed
   `npm pack` says the starter could not be downloaded, names the spec and
   suggests checking the name or the network. A failure after the target
   folder was created leaves no half-written site: remove the folder you
   created (never for `nera new .`; there, report which files were written).
