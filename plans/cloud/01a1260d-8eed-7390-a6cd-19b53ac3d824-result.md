## Summary

`nera new` can start from a starter kit: `--starter <spec>` (bare name,
package, GitHub URL, local path) lays the starter's `pages/`, `config/`,
`theme/`, `assets/`, `plugins/` and `.neraignore` over the base template,
merges its `dependencies`, and prints its README. `--name` / `--lang` set
`name:` / `lang:` in `config/app.yaml`, with or without a starter. On a
terminal, without `--starter` or `--yes`, a picker asks for the starter
(npm registry, bundled fallback), name and language. New code in
`src/starter.js`, `src/starters.js`, `src/prompt.js`; `scaffoldProject`
(`src/scaffold.js`) stays the one entry point; `src/commands/new.js` only
parses and prompts. Without a TTY, output and files are byte-for-byte as on
`main`.

## Decisions

- Branch: the brief names `issue/01a1260d-nera-new-starter`; the cloud session was set up on `claude/nera-new-starter-eahn33`. The work is on `issue/01a1260d-nera-new-starter` (created from `origin/main`; the session's local `main` was stale at 1.8.0), and the same commits are pushed to both branch names.
- `--starter` also accepts an **absolute** local path (`/abs/x`), which the "Done when" check uses; the path characters are `LOCAL_THEME`'s (`[A-Za-z0-9._-]`), so paths with spaces are refused. Windows drive paths are not accepted.
- Unscoped package names are recognised only as `nera-starter-<x>`; any other lowercase name is a bare name (`my-blog` → `@nera-static/starter-my-blog`). GitHub refs may contain `/` but not start with `-`. `http://`, other hosts and `git+ssh:` are refused.
- The picker lists only registry results whose shown name maps back to the same package (an unscoped `cool-site` with the keyword is left out, as `--starter cool-site` would mean `@nera-static/starter-cool-site`). An empty registry result is not a failure: the picker then offers only "Empty" (it does not merge the bundled list, which would offer `blank` before it is published).
- Bundled entries show as `blank — Blank: The smallest Nera starter: …` (label + description); registry entries show their npm `description`.
- The picker also accepts a starter's shown name instead of its number and asks again on an invalid answer; end of input takes the defaults.
- Pressing Enter at "Site name" / "Language" leaves `config/app.yaml` as the template or the starter has it (no `name`/`lang` passed). The prompt shows `[My Nera Site]` / `[en]` for "Empty" and `[the starter's]` after picking a starter, so the starter's own values are never fetched before scaffolding.
- With `--theme` on a TTY, the picker skips "What are you building?" (a starter would be an error) but still asks name and language. With `--starter`, nothing is asked (decision 7).
- Bad flags (project name, `--theme`, `--name`, `--lang`) are rejected before the first question.
- `--name` must be non-empty and contain no control characters (no line breaks); `--lang` uses the brief's pattern. `setAppValue` replaces the whole top-level line, so an inline comment on `name:`/`lang:` is dropped.
- The starter is fetched and its manifest checked **before** the target folder is created; a failure after creation removes the folder (`nera new <name>`) or lists the files written (`nera new .`). A failing `npm install` at the end does **not** remove the site: the files are complete, and the error is npm's own as today.
- Symlinks in a starter are not copied. Dependency values that are not strings are ignored.
- A log line `📦 Downloading the starter "<spec>"...` before `npm pack`, and `✓ Applied the "<label>" starter (<package name>)` after the copy; the README is printed between "✅ Done!" and "👉 Next steps".
- `src/starters.js` instead of `.json`, so the "hand-kept" comment can live in the file.
- Ctrl+C in the picker exits 1 with "Cancelled — nothing was created."

## Review hints

- `npm pack github:<owner>/<repo>` with `--ignore-scripts`: verified on Linux with a real public repo (packed and extracted). On Windows: `npm` vs `npm.cmd` with `execFileSync` (no shell) and the presence of `tar` (bsdtar ships with Windows 10+) are unverified.
- Whether `npm pack` of a git dependency honours `--ignore-scripts` for `prepare` on every npm version the engines range allows (npm 10/11). Tested with the npm bundled with Node 22.22.0 only, and only with a repo that has no `prepare`.
- The picker on a real terminal was driven through a Python pty, not a human terminal; arrow keys, paste and Windows consoles are untested. Ctrl+C is handled via readline's `SIGINT` event.
- `src/prompt.js` marks end of input with `rl.ended` on the readline interface (an ad-hoc property).
- `setAppValue` matches `^key:` at column 0; a top-level key written with quotes (`"name": x`) would not be found and a second line would be appended.
- Today the registry has no starters, so the picker shows a one-entry list ("Choose 1–1"). A reviewer may prefer skipping that question while the list is empty.
- `test/build.test.js` drops `@nera-static/plugin-navigation` from its fixture copy, since it cannot be installed offline; the merged dependency is therefore not exercised by a build.
